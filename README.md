# Практическая № 8 · цифровая теплица

Локальный стенд для демонстрации обмена по USART между двумя STM32L031K6. Модель среды вычисляет показания семи датчиков. Первая прошивка на C выбирает действие, вторая проверяет команду и управляет приводами. Состояние исполнительной платы возвращается в модель и влияет на следующие показания.

## Запуск с Wokwi

Понадобятся Python 3.11+, VS Code с расширением **Wokwi Simulator** и активированной лицензией Wokwi, GNU Make и компилятор `arm-none-eabi-gcc` для пересборки. Готовые ARM-файлы для Wokwi лежат в папках проектов.

Из каталога с этим README:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python app.py
```

Если расширение ещё не активировано, выполните `Wokwi: Request a New License` и завершите [активацию Wokwi](https://docs.wokwi.com/vscode/getting-started#installation) в VS Code.

1. Откройте **отдельными окнами VS Code** папки `firmware/controller` и `firmware/actuator`. В каждой находятся `diagram.json` и `wokwi.toml`.
2. В каждом окне выполните `Wokwi: Start Simulator`. Оставьте обе вкладки симуляции видимыми. Порты первой и второй платы — `4001` и `4002`. Сервер подключится к ним автоматически, в том числе если симуляторы запустились позднее.
3. Откройте [панель теплицы](http://127.0.0.1:8000). Индикатор должен показать связь с обеими платами, а в журнале появятся `STATUS?`, `STATE:0,0,0,0` и пакеты `SENS:…`. Порт панели можно изменить ключом `--port`.

Пересобрать ARM-прошивки и проверить логику на компьютере:

```sh
make -C firmware
make -C firmware test
.venv/bin/python -m unittest discover -s tests
# При запущенном сервере на порту 8000
.venv/bin/python tests/e2e.py
```

На Windows команды можно выполнить в окружении с GNU Make, например в WSL. VS Code и Python-мост для Wokwi должны видеть одни и те же локальные порты. Если запускаете Python в Windows, путь к интерпретатору виртуального окружения — `.venv\Scripts\python.exe`.

## Локальная демонстрация

```sh
make -C firmware native
.venv/bin/python app.py --demo
```

На macOS и Linux этот режим запускает на компьютере два процесса, собранных из того же управляющего кода C. Можно проверить датчики, протокол, логику приводов и веб-панель. На экране режим обозначен явно. ШИМ, выводы GPIO и работу расширения Wokwi проверяют при запуске симуляций.

## Порядок защиты

Нажмите «Показать на примере жары». Панель покажет входной кадр модели, команду МК 1, ответ МК 2 и результат по показаниям. Выберите плату или привод на схеме, чтобы увидеть его роль и состояние. Кнопка «Объём» переключает вид теплицы.

Перед каждым опытом автоматика возвращает приводы в исходное положение. Повторный полив ждёт окончания паузы. «Сброс» завершает текущий опыт и возвращает модель к обычному дню.

| Сценарий | Что наблюдать |
|---|---|
| Жара | `SERV:090;` → движение сервопривода → `OK` → охлаждение по графику |
| Яркое солнце | `STEP:FWD,200;` → штора выдвигается. Наружный свет остаётся высоким, над грядкой падает |
| Сброс после яркого солнца | `STEP:REV,200;` → штора убирается |
| Сухой грунт | `PUMP:003;` → синий LED загорается на 3 с, вода убывает, влажность грунта растёт |
| Пустой бак | МК 1 сообщает `INFO:IRRIGATION,WATER`, помпа остаётся выключенной |
| Сбой датчика | Поле влажности грунта передаётся как `NA`. МК 1 отвечает `INFO:IRRIGATION,SENSOR` |
| Холодное утро | Температура стекла опускается ниже точки росы, видны капли; проветривание снижает влажность |
| Ошибочный угол | МК 1 отправляет `SERV:181;`. МК 2 отвечает `ERROR` и оставляет приводы в исходном положении |

Для проверки ошибок остановите веб-сервер, оставьте симуляцию исполнительной платы активной и подключитесь к её порту:

```sh
.venv/bin/python -m serial.tools.miniterm rfc2217://127.0.0.1:4002 115200 --eol LF
```

Введите `STATUS?` и нажмите Enter. Затем отправьте `SERV:181;`, `STEP:FWD,0;` и `GARBAGE`. На каждую ошибочную строку должен прийти `ERROR`. Если штора убрана, `STEP:REV,1;` проверяет границу хода. После проверки закройте терминал, чтобы освободить порт для веб-сервера.

В схеме исполнительной платы присутствует логический анализатор. Чтобы записать импульсы, выполните сценарии в Wokwi и остановите симуляцию. Расширение сохраняет VCD. В PulseView или GTKWave выберите UART 115200 8N1, измерьте период PWM 20 мс и пересчитайте фронты STEP. Полезно сохранить скриншоты команд, ответов и двух направлений в отчёт. [Экспорт VCD](https://docs.wokwi.com/vscode/project-config#logic-analyzer-vcd-export)

## Обмен

- Обе платы используют `USART2`, 115200 бод, 8N1. Терминатор кадра — LF, допустим CRLF. Точка с запятой остаётся частью команды.
- `SENS:240,64,48,43,60,75,230` содержит температуру воздуха в десятых градуса, влажность воздуха, наружный и внутренний свет, влажность грунта и уровень воды в целых процентах, затем температуру стекла в десятых градуса. Отсутствующее поле — `NA`.
- `STATE:90,200,0,0` означает заданный угол 90°, позицию шторы 200 шагов, выключенную помпу и свободный исполнитель. Угол и шаги — данные прошивки о заданной позиции. Приём и выходные сигналы можно сверить в симуляции.
- `DIAG:ANGLE` запускает проверку ошибочного угла. `INFO:IRRIGATION,…` сообщает мосту о смене причины блокировки полива.
- При проводном соединении TX первой платы идёт к RX второй, RX первой — к TX второй, земли соединяются. В этом стенде каждый USART подключён к своему виртуальному последовательному порту. RFC2217 и локальный мост переносят кадры между двумя симуляциями. [Ограничение Wokwi](https://docs.wokwi.com/faq#how-do-i-use-multiple-microcontrollers-in-a-single-project)

Модель использует нормированные проценты влажности грунта и света и коэффициенты, подобранные для короткой демонстрации. Они задают поведение учебного стенда.
